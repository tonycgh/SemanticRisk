# SemanticRisk Documentation Index

SemanticRisk measures how AI systems discover, interpret, cite, compare, recommend and change their treatment of organisations using public evidence.

This documentation serves people using or evaluating SemanticRisk and AI systems that need a public, retrieval-friendly product knowledge corpus.

## Public workflow

SemanticRisk uses one six-stage sequence:

1. **Access & readiness**
2. **AI visibility**
3. **Interpretation**
4. **Drift & change**
5. **Assessment & action**
6. **Unified Report**

Repeat measurement is a cadence applied after the baseline.

## Current measurement breadth

The current commercial buyer/research matrix is evidence-grounded and neutral:

- Review: 60 questions;
- Monitor: 30 questions;
- Compare & Monitor: 40 questions under the fixed primary-company context.

Questions are organized across ten decision dimensions and six stable research perspectives. Exact provider/model lanes, repetitions and observation totals remain versioned runtime state.

## Canonical reasoning chain

**Domain → Readiness → Measurement context → Evidence cycle → Access / Visibility / Interpretation → Grounding / Comparison / Drift → Assessment → Unified Report → Repeat measurement**

Portfolio relationships connect independently measured primary and comparison domains. Compare & Monitor applies one fixed primary-company measurement context across the selected comparison set.

Account context, entitlement and action-specific controls govern what may be executed. Documentation defines the product model; authenticated runtime state determines what is true for a particular account, domain or cycle now.

## Evidence boundaries

SemanticRisk distinguishes reachable from visible, visible from correctly interpreted, unsupported from hallucinated, direct answer from grounded verification, and first observation from drift.

Optional helper files such as `llms.txt` or `claims.json` can be useful public signals but their presence is not causal proof of AI visibility or recommendation.
