# Measurement Context and Readiness

This page defines the public setup that precedes commercial SemanticRisk AI measurement and the lightweight public re-check used after evidence exists.

## Free Public Check and readiness

SemanticRisk can inspect a public domain before signup or purchase to determine whether useful public evidence is reachable and what discovery resources appear to be available.

Readiness can inspect resources such as `robots.txt`, sitemap discovery, `llms.txt`, `llms-full.txt`, `claims.json` and `claims.txt`, but optional helper files are not prerequisites for measurement and are not visibility guarantees.

A readiness check does not itself create a Comprehensive Review or subscription.

## Evidence-grounded measurement context

Before controlled AI measurement begins, SemanticRisk needs a defensible versioned context. It can include:

- organisation/entity;
- broad sector;
- buyer-facing category;
- buyer decision need;
- decision/risk need;
- geography when relevant.

The context can be derived from current site evidence, supported historical evidence, governed taxonomy or customer-confirmed context.

High-confidence SemanticRisk-owned context can be persisted automatically as a new immutable profile version. Customer-confirmed category context and genuinely custom buyer/risk wording should not be silently replaced. Lower-confidence proposals should not replace a defensible current profile without review.

Broad terms such as `global`, `worldwide` and `international` represent unbounded geography rather than literal locations. This prevents malformed question wording such as "in global".

## Current question-plan application

Once context is ready, the current commercial matrix uses:

- Review: 60 neutral buyer/research questions;
- Monitor: 30 questions;
- Compare & Monitor: 40 questions.

Questions are rendered from the governed context and must not be written to force the evaluated organisation into discovery/recommendation answers.

Exact provider/model lanes, repetitions and observation totals are versioned runtime state.

## Context versioning

A running or completed evidence cycle remains bound to the profile version used when it began. A later profile change creates a new version; it does not rewrite earlier observations or reports.

Entity/sector/category labels in a frozen report should come from sufficiently confident classification bound to the same evidence cycle, not from unrelated later classification.

## Compare & Monitor primary context

Compare & Monitor anchors the selected comparison set to the fixed primary company's measurement context. Competitor domains are evaluated under that common buyer/category frame for comparability while retaining their own independent domain evidence.

The current plan supports the primary domain plus up to three selected competitors.

## Live re-check

After a completed evidence cycle exists, a lightweight live re-check can compare current public discovery state with the report's evidence baseline.

Relevant signals can include access state, helper-file presence/validity, sitemap sources, discovered URL counts and eligible-page counts. A lightweight re-check must not overwrite the deeper evidence baseline from the completed report.

A material change can support a recommendation to run a new entitled cycle. The re-check itself is not a new Review or subscription charge.

## AI assistant rules

Use runtime state for current profile version, readiness, re-check results and entitlement. Preserve profile-version boundaries, do not invent context from general knowledge, do not treat helper-file presence as causal proof, and do not imply that merely reviewing setup or selecting a competitor started paid measurement.
