# Unified Report

The Unified Report is the customer-facing frozen evidence artifact for a completed SemanticRisk evidence cycle.

It is not a transient dashboard summary. Later workspace state, live re-checks, newer cycles or presentation improvements must not silently rewrite the evidence that produced an earlier completed report.

## Evidence binding

A report is bound to the representative website evidence, measurement-context version, controlled AI observations, interpretation/provenance evidence and compatible comparison/drift evidence available for that cycle.

If evidence was not captured or persisted, the report should state the limitation rather than manufacture exact values, model narratives, citations or causes.

A structurally invalid artifact remains auditable but is not a normal customer trend baseline.

## Executive summary

The first part of the report should give a decision-maker a concise view of:

- current AI visibility and interpretation evidence;
- important competitor/comparison outcomes where measured;
- material representation/grounding or claim-support issues;
- highest-priority evidence-backed actions;
- conditions worth monitoring;
- supported advantages;
- whether repeat measurement would add useful evidence.

The summary is downstream of the underlying evidence and must not convert inference into observation.

## Headline evidence dimensions

Headline measures are not interchangeable scores.

- **Buyer/research presence** describes whether the target surfaced across the controlled question set.
- **Recommendation/shortlist outcome** is distinct from simple mention.
- **Citation/source behaviour** describes observable support/provenance in the measured answer or later verification layer, depending on mode.
- **Interpretation** describes how the organisation is classified and represented.
- **Claims extracted** are evidence volume, not a quality score.
- **Drift** requires compatible repeat cycles. The first valid report is a baseline.

## Direct AI representation and grounded verification

Where configured, SemanticRisk preserves the direct measured AI answer before later grounded verification.

Grounded verification can compare statements with current public evidence and attach provenance, but it must not replace the original measured answer.

The difference between an observed AI statement and current reference evidence can be described as a **Representation / Grounding Gap**. It is not automatically longitudinal drift.

Where evidence permits, statements can be assessed as Supported, Partially supported, Unsupported / unverified, Contradicted, Outdated / stale, or Unverifiable. Unsupported is not automatically hallucinated.

## Compare & Monitor

Where a compatible comparison cycle exists, the primary domain's Unified Report can include:

- companies surfaced or omitted;
- category association;
- recommendation or shortlist outcomes;
- interpretation and material representation gaps;
- citation/source support;
- competitor displacement;
- **Do this**, **Watch this**, and **Advantage** findings;
- observation-level evidence with confidence/provenance.

The report should explain the evidence pattern and supported next action rather than merely say that a competitor is "ahead". Comparison evidence is diagnostic and is not consumer AI market share.

## Website and readiness evidence

Depending on what was measured, the report can include access/discovery state, sitemap evidence, helper-file evidence, representative page evidence, recurring claims and cross-page tensions.

Helper-file presence is not proof that an AI provider used the file or that it caused a visibility or recommendation outcome.

## Recommendation cycle

Recommendations follow:

**Observe → Explain → Change → Re-measure → Verify**

A recommendation is a testable next step, not proof that the proposed change will improve downstream AI behaviour.

## Appendices and provenance

A detailed report may include question identifiers, prompts where appropriate, observation ledger, provider/model lane, measurement mode, timestamps, question-plan/probe version, direct response excerpts, grounded evidence, source URLs, claim assessments, site inventory and methodology notes when those fields were persisted.

Missing fields should be stated explicitly rather than reconstructed after the fact.

## Entitlement and repair

A Comprehensive Review or active subscription grants the report/evidence access defined by current runtime entitlement. Compatible current evidence can be reused when the product's entitlement and evidence rules permit it.

If a system-caused structurally invalid report must be replaced, the product can reuse the existing Review/subscription entitlement when runtime state marks the repair eligible. The customer should not be forced to repurchase the same failed outcome.

## Repeated measurement and drift

Repeated compatible measurement is required for longitudinal drift. If the immediately preceding artifact is invalid or methodologically incompatible, SemanticRisk should use an exact valid comparison when available or state **Comparable drift unavailable**.

## AI assistant rules

When explaining a report, distinguish visibility from interpretation, direct measured answer from later grounded verification, supporting URLs from original direct-answer citations, baseline from drift, claim volume from quality, surfacing from recommendation, unsupported from hallucinated, helper-file signal from causal proof, and recommendation from verified effect.

Use authenticated runtime state for current report availability, entitlement, freshness and work in progress.
